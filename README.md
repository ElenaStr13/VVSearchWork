# VV Work

VV Work — MVP-платформа для пошуку роботи та працівників у Європі.

Проєкт виконаний як тестове завдання на позицію Front-end Developer.

## Технології

- React
- TypeScript
- Vite
- Tailwind CSS
- React Router
- Vitest
- React Testing Library

## Реалізований функціонал

- Головна сторінка з основною інформацією про платформу.
- Сторінка зі списком усіх вакансій.
- Динамічні сторінки роботодавців `/partners/:slug`.
- Перехід до вакансій конкретного роботодавця.
- Пошук вакансій за назвою з debounce.
- Фільтрація вакансій за категоріями.
- Спільна робота пошуку та фільтра категорій.
- Перехід до вакансій вибраної категорії з головної сторінки.
- Форма відгуку на вакансію з inline-валідацією.
- Optimistic UI під час надсилання заявки.
- Обробка помилки надсилання заявки.
- Імітація API-запитів із випадковою затримкою та помилками.
- Skeleton під час завантаження даних.
- Retry при помилці завантаження.
- Адаптивна верстка для desktop, tablet та mobile.
- Спільні Header і Footer.

## Мої рішення

- **Структура Головної сторінки.** На початку розмістила Hero з коротким поясненням призначення VV Work і двома основними діями — «Знайти роботу» та «Знайти працівника». Нижче винесла популярні категорії, роботодавців і окремий CTA для роботодавців, щоб основні сценарії були доступні без зайвих переходів.

- **Швидкий пошук вакансій.** Додала перехід із популярних категорій на вже відфільтрований список вакансій, а на сторінці вакансій поєднала пошук за назвою та фільтр за категорією. Для пошуку використала debounce 500 мс.

- **Стейт-менеджмент без Redux/Zustand.** Для MVP використала локальний React state (`useState`, `useEffect`), оскільки стан компонентів невеликий і не потребує глобального store. Категорію вакансій також зберігаю в URL query-параметрі, що дозволяє переходити на вже відфільтрований список.

- **Зменшення зайвих обчислень і ре-рендерів.** Відфільтрований список вакансій мемоізований через `useMemo`, функція завантаження — через `useCallback`, а debounce не дозволяє запускати фільтрацію після кожного натискання клавіші.

- **Зміни відносно брифу.** Замість окремого пункту «Партнери» в Header зробила перехід на динамічну сторінку роботодавця безпосередньо з його назви/картки. Для пошуку роботи додала окремий маршрут `/vacancies` зі всіма вакансіями, тоді як `/partners/:slug` показує вакансії конкретного роботодавця. 
## Робота з API

Для імітації реального API використовується власний `mockFetch`.

Він додає:

- випадкову затримку запиту 300–800 мс;
- приблизно 20% ймовірності помилки;
- обробку станів loading/error;
- можливість повторити запит через Retry.

## Валідація форми

Форма відгуку перевіряє:

- ім'я — мінімум 2 символи;
- телефон або Telegram — перевірка формату;
- повідомлення — максимум 500 символів.

Помилки відображаються безпосередньо біля відповідних полів.

## Тестування

Для тестування використані Vitest та React Testing Library.

Автоматичними тестами перевіряються:

- debounce пошуку;
- валідація форми;
- успішне надсилання форми;
- rollback optimistic UI при помилці;
- Retry після помилки завантаження вакансій.

Запуск тестів:

```bash
npm run test:run
```

Запуск тестів із coverage:

```bash
npm run coverage
```

Поточне загальне покриття логіки:

```text

Branches:   79.16%
Functions:  79.31%

```

## Запуск проєкту

Встановити залежності:

```bash
npm install
```

Запустити development server:

```bash
npm run dev
```

Створити production build:

```bash
npm run build
```

Переглянути production build локально:

```bash
npm run preview
```

## Структура

Основна логіка проєкту розділена на:

- `components` — перевикористовувані UI-компоненти;
- `pages` — сторінки застосунку;
- `services` — робота з mock API;
- `data` — тестові дані вакансій і роботодавців;
- `types` — TypeScript-типи;
- `router` — маршрутизація;
- `layouts` — спільний layout;
- `styles` — глобальні стилі.
